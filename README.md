# Oktopus

**[English](README.en.md)**

**Документация:** [русский](docs/ru/index.html) · [English](docs/en/index.html)

Oktopus — система контроля исходящего интернет‑трафика организации: единая точка выхода (HTTP/HTTPS‑прокси), понятные правила «кто куда может ходить», журнал решений и веб‑кабинет для администраторов. В режиме MITM прокси может не только разрешать или блокировать сайты, но и **проверять исходящие HTTP‑запросы** по своим правилам после прохождения ACL.

Подходит, когда нужны корпоративный фильтр доступа, аудит, интеграция с LDAP, знакомый синтаксис Squid (`acl`, `http_access`) и настраиваемые страницы отказа для пользователей.

## Возможности


| Область               | Что даёт система                                                                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Контроль доступа**  | Политика в стиле Squid: источник, назначение, домены/SNI, порты, URL, группы LDAP, именованные списки; порядок `http_access`, задержки, проверка TLS к origin |
| **Режимы прокси**     | **Tunnel** (CONNECT без расшифровки) и **MITM** (расшифровка HTTPS с корневым CA на клиентах); plain HTTP, WebSocket в MITM                                   |
| **Инспекция**         | После allow по ACL — цепочка правил на Lua для исходящих запросов (заголовки, тело, действия allow/deny); только в MITM                                       |
| **Аутентификация**    | Вход клиентов в прокси: локальные учётки или LDAP; правила ACL могут опираться на группы каталога                                                             |
| **Панель управления** | Запуск/остановка прокси, редактор ACL и инспекции, пользователи API, журнал access log, отчёты, инспектор «почему сработало правило»                          |
| **Журнал и отчёты**   | Хранение решений allow/deny с контекстом (хост, пользователь, правило, инспекция) для расследований и отчётности                                              |
| **Проверка политики** | В CI — интеграционные тесты ACL и сценарии попыток обхода; через API evaluate можно получить allow/deny по полям запроса без прогона трафика через прокси     |


## Пропускная способность

Замеры **на localhost** (генератор нагрузки и прокси на одной машине), CPU **6 ядер ~4.3 GHz**, в политике порядка **~1.5 млн** проверок SNI и включена **инспекция исходящих** (MITM). Инструмент: `go run ./cmd load`.


| Показатель                                                                          | Значение                          |
| ----------------------------------------------------------------------------------- | --------------------------------- |
| Пик RPS, сценарий **allow** (запрос проходит ACL, инспекцию и дальнейшую обработку) | до **~14 000 запросов в секунду** |
| Пик RPS, сценарий **deny** (отказ на ACL, без полного проксирования к origin)       | до **~45 000 запросов в секунду** |
| Среднее время **ACL + inspect** на запрос                                           | **< 1 ms**                        |
| Потребление RAM процессом прокси в этом режиме                                      | **~600 MB**                       |


## Быстрый старт (Docker)

Требуются Git и [Docker Compose](https://docs.docker.com/compose/). Пошагово — в [документации: развёртывание](docs/ru/quickstart.html).

```bash
git clone https://github.com/Camyil-89/oktopus.git
cd oktopus
```

**Linux / macOS:** `./scripts/stack-up.sh` — создаёт `.env`, собирает и поднимает стек, выводит URL UI и пароль администратора.

**Windows:** `scripts\stack-up.bat` (использует `docker-compose.desktop.yml`).

После входа в кабинет убедитесь, что прокси **RUNNING**, и укажите клиентам listen‑адрес из [настроек прокси](docs/ru/manage/proxy.html).

## Разработка

1. Зависимости: `docker compose -f docker-compose.dev.yml up -d`.
2. `.env.example` → `.env` в корне.
3. `go run ./cmd serve` (API по умолчанию `http://127.0.0.1:8000`).
4. UI: `web/` — `npm install`, `npm run dev`; `NEXT_PUBLIC_API_URL=http://localhost:8000` в `web/.env.local`.

Подробнее: [раздел для разработчиков](docs/ru/index.html). Карта страниц: [docs/DOC_MAP.md](docs/DOC_MAP.md). Сборка сайта docs: `node docs/build.mjs`.

## CLI

```text
go run ./cmd serve          # API + прокси, миграции при старте
go run ./cmd load [флаги]   # нагрузочный GET через HTTP‑прокси
```

```bash
go run ./cmd load -url=https://example.com/ -workers=32 -duration=30s -proxy=127.0.0.1:8080
```

## Технологии

Go (прокси и API), Next.js (кабинет), PostgreSQL (настройки и политика), ClickHouse (журнал); OpenLDAP — только в dev-окружении для проверки интеграции с каталогом.
