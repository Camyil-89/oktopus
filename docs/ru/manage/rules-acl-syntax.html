Синтаксис ACL

Формат конфигурации на вкладке «ACL / http_access» в кабинете. Синтаксис близок к Squid: строки читаются сверху вниз, комментарии — с #.

ACL / http_access Инспекция
# ваш конфиг acl all all http_access deny all

Подсказка

Наведите на элемент

Справочник описывает текст ACL на странице правил инстанса.

Порядок применения

  1. Сначала объявляются все acl (имя + тип + значения).
  2. Затем http_access: для каждого запроса проверяются строки по порядку; первая подошедшая строка с allow или deny завершает решение.
  3. Если ни одна строка не подошла — запрос запрещается (запрет по умолчанию).

Типы acl

ТипНазначениеПример значений
srcIP клиента10.0.0.0/8 192.168.1.5
dstIP назначения203.0.113.10
dstdomain, sniДомен / SNI (HTTPS).example.com github.com
portПорт назначения80 443 8080
url_regexПуть URL (MITM / HTTP)^/api/private
ldap_groupГруппа LDAP (если настроена auth)имя группы
allВсегда истинабез значений: acl all all

http_access

Формат: http_access allow|deny затем имена acl через пробел. Префикс ! перед именем — отрицание («клиент не из этого acl»).

пример
acl office src 10.10.0.0/16
acl bad_sites dstdomain .ads.example
acl all all

http_access deny bad_sites
http_access allow office
http_access deny all

Дополнительные директивы

  • ssl_verify require|skip — проверка сертификата upstream (по acl, как http_access).
  • delay_pools, delay_class, delay_access — ограничение скорости (продвинутая настройка).

Lists в кабинете

Вместо длинных списков в одном файле можно завести List (src / dstdomain / port), заполнить вручную или подтянуть по URL. В конфиге появится acl с тем именем, которое вы задали — используйте его в http_access.

Проверка

После сохранения смотрите диагностику в редакторе и карточку «Сборка ACL» на главной. Ошибки компиляции нужно исправить до публикации — иначе может остаться предыдущая рабочая версия правил.

промпт
Ты эксперт по конфигурации ACL для корпоративного прокси Oktopus. Формат как у Squid: текст вставляется во вкладку «ACL / http_access» в веб-кабинете. Комментарии — строки с #.

=== Как читается конфиг ===
1) Сначала все директивы acl <имя> <тип> <значения…> — имя уникально, значения через пробел.
2) Потом http_access allow|deny <имя_acl> … — для каждого запроса строки проверяются сверху вниз; первая подошедшая allow или deny завершает решение.
3) Если ни одна строка http_access не сработала — запрос запрещается (implicit deny).
4) Перед именем acl в http_access можно поставить ! — отрицание (условие «НЕ совпало с этим acl»).

=== Типы acl (Oktopus) ===
• src — IP клиента (подсеть CIDR или хост): acl office src 10.10.0.0/16 192.168.1.5
• dst — IP назначения (после резолва, полезно в tunnel): acl loopback dst 127.0.0.0/8
• dstdomain — домен назначения; точка в начале = суффикс (.google.com совпадает с www.google.com)
• sni — SNI в HTTPS (в tunnel часто только sni/dst, без пути URL)
• port — порт назначения: acl ssl_ports port 443 8443
• url_regex — путь URL (регулярное выражение); работает при MITM или для обычного HTTP, не для «чистого» tunnel без расшифровки
• ldap_group — членство в группе LDAP (если в прокси настроена LDAP-аутентификация): acl admins ldap_group IT-Admins
• all — всегда true: acl all all

=== Lists в кабинете ===
Длинные списки IP/доменов/портов можно вынести в List (типы src, dstdomain, port). В конфиге появится acl с заданным именем списка — используй это имя в http_access так же, как обычный acl.

=== http_access — типовые шаблоны ===
Запрет рекламы/вредоносных доменов для всех:
  acl bad dstdomain .ads.example .malware.example
  acl all all
  http_access deny bad
  http_access deny all

Офис пускаем, остальным закрыто:
  acl office src 10.0.0.0/8
  acl all all
  http_access allow office
  http_access deny all

Сначала узкие deny, потом allow, в конце deny all:
  acl blocked dstdomain .facebook.com
  acl devs src 10.20.30.0/24
  acl all all
  http_access deny blocked
  http_access allow devs
  http_access deny all

Отрицание — «разрешить всем, кроме подсети»:
  acl guests src 192.168.100.0/24
  acl all all
  http_access deny !guests all
  http_access allow all

Tunnel: запрет localhost по IP, разрешение по имени:
  acl public dstdomain localhost
  acl loopback dst 127.0.0.0/8
  acl all all
  http_access deny loopback
  http_access allow public
  http_access deny all

MITM + путь: acl private_api url_regex ^/api/internal
  (добавь http_access deny private_api или allow по задаче)

=== Дополнительно (если уместно) ===
• ssl_verify require|skip <acl…> — требовать или пропускать проверку сертификата upstream для совпавших запросов.
• delay_pools, delay_class, delay_access — лимиты скорости (продвинуто).
