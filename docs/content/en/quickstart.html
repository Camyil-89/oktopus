Deployment

Deployment

Run Oktopus in Docker: the stack script writes .env, starts Compose, and prints the control panel URL and admin credentials.

Stack services

docker compose from the repo root runs four services (see docker-compose.yml). Together they form one Oktopus installation on your network:

  • nginx — entry point for administrators: serves the Next.js UI and proxies browser requests to the Oktopus HTTP API. This is the URL the stack script prints (OKTOPUS_API_HOST / OKTOPUS_API_PORT).
  • oktopus — single application container (go run equivalent): forward HTTP/HTTPS proxy, REST API, and proxy engine. Client traffic uses the proxy listen port from the panel; administrators use nginx for the UI.
  • postgresql — operational data: users, proxy settings, ACL rules, sessions, and other metadata the API reads and writes.
  • clickhouse — high-volume proxy access log and analytics for reports; written by the proxy, queried by the API for the access log UI.

PostgreSQL and ClickHouse are published on localhost only (ports from .env).

Requirements

  • Docker Compose (docker compose); Git is optional if you use the one-command installer.
  • Windows: Docker Desktop. Linux: docker-compose.yml from the release bundle or repository.

One-command install

The minimal deploy set (compose, ClickHouse init, stack-up) is attached to each GitHub Release as oktopus-<version>-deploy.tar.gz. scripts/install.sh (or install.ps1) downloads that archive, extracts it (default ./oktopus), and runs stack-up with a registry pull for GHCR images.

bash
curl -fsSL https://raw.githubusercontent.com/Camyil-89/oktopus/main/scripts/install.sh | bash

Pin a version: curl -fsSL ... | bash -s -- --version 1.2.3. Install dir: OKTOPUS_INSTALL_DIR=/opt/oktopus or --dir /opt/oktopus. Download only: --fetch-only. Non-interactive: set OKTOPUS_API_HOST and OKTOPUS_API_PORT before running.

Windows (PowerShell):

PowerShell
irm https://raw.githubusercontent.com/Camyil-89/oktopus/main/scripts/install.ps1 | iex

From a git checkout, ./scripts/install.sh without --fetch delegates to stack-up.sh (handy when developing).

Clone (optional)

shell
git clone https://github.com/Camyil-89/oktopus.git
cd oktopus

Versions and container images

Product version is SemVer in web/package.json (shown in the UI). After CI succeeds on main, GitHub Actions publishes images to GHCR with tags <version> and latest, creates git tag v<version>, and a GitHub Release with a deploy tarball.

  • ghcr.io/camyil-89/oktopus/oktopus:latest — API and proxy
  • ghcr.io/camyil-89/oktopus/nginx:latest — UI and reverse proxy

The stack script runs docker compose pull for these images by default (OKTOPUS_IMAGE and OKTOPUS_NGINX_IMAGE in .env). Local build: ./scripts/stack-up.sh --build or OKTOPUS_COMPOSE_BUILD=1.

If GHCR packages are private, run docker login ghcr.io on the server (PAT with read:packages) or make the packages public in GitHub settings.

Linux and macOS

scripts/stack-up.sh prompts for API host and port (or set OKTOPUS_API_HOST / OKTOPUS_API_PORT), regenerates .env, pulls images from the registry, then runs docker compose -f docker-compose.yml up -d.

bash
chmod +x scripts/stack-up.sh
./scripts/stack-up.sh

Env only (e.g. Portainer): ./scripts/stack-up.sh --write-env-only.

Windows

scripts\stack-up.bat uses docker-compose.desktop.yml. From the repo root:

cmd
scripts\stack-up.bat

Env only: scripts\stack-up.bat --write-env-only. OKTOPUS_API_HOST / OKTOPUS_API_PORT skip prompts.

After startup

  1. The script prints UI URL, admin login, and password from .env.
  2. Sign in and confirm the proxy is RUNNING on Home.
  3. On Home, create a proxy instance (name and listen), then set port, tunnel/MITM, and CA under instance settings; point clients at that listen address.

Re-running the script recreates .env but keeps DB passwords when Docker volumes already exist.
