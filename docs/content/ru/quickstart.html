Развёртывание

Запуск Oktopus в Docker: скрипт создаёт .env, поднимает compose и выводит URL панели управления и учётные данные администратора.

Что нужно

  • Git и Docker Compose (команда docker compose).
  • На Windows — Docker Desktop; на Linux — обычный docker-compose.yml в корне репозитория.

Клонирование

shell
git clone https://github.com/Camyil-89/oktopus.git
cd oktopus

Linux и macOS

Скрипт scripts/stack-up.sh спросит хост и порт API (или задайте OKTOPUS_API_HOST и OKTOPUS_API_PORT в окружении), пересоздаст .env и выполнит docker compose -f docker-compose.yml up --build -d.

bash
chmod +x scripts/stack-up.sh
./scripts/stack-up.sh

Только сгенерировать .env без запуска (например, для Portainer): ./scripts/stack-up.sh --write-env-only.

Windows

Скрипт scripts\stack-up.bat использует docker-compose.desktop.yml (сеть bridge для Docker Desktop). Запуск из корня репозитория:

cmd
scripts\stack-up.bat

Только .env: scripts\stack-up.bat --write-env-only. Переменные OKTOPUS_API_HOST / OKTOPUS_API_PORT тоже отключают интерактивные вопросы.

После запуска

  1. В конце скрипт выведет UI (http://…), логин и пароль администратора из .env.
  2. Откройте URL в браузере, войдите и на главной проверьте, что прокси RUNNING.
  3. Порт и режим прокси — в настройках прокси; клиентам укажите listen-адрес из панели.

При повторном запуске скрипт пересоздаёт .env, но пароли БД сохраняются, если тома Docker уже существуют.
